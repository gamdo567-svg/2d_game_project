## D-003 모듈 구조와 계층 분리

- 상태: 채택
- 날짜: 2026-11-02
- 결정
  - `game/` 아래를 `core`(루프·시간), `input`, `world`(칸 좌표·맵), `physics`(충돌), `render`, `scenes`로 나눕니다.
  - pico2d import는 `core/app.py`, `input/pico2d_input.py`, `render/` 세 곳으로 제한합니다.
  - 장면은 `update(dt, input_state)`(로직)와 `draw(renderer)`(그리기)로 나눕니다.
- 이유: 입력·로직·충돌·렌더링 분리 요구를 만족하면서, 로직을 창 없이 단위 테스트할 수 있게 합니다.
  엔티티-컴포넌트 시스템 같은 무거운 구조는 현재 규모에 비해 복잡하므로 쓰지 않습니다.
- 대안: 파일 하나에 모든 코드 작성 (초기엔 빠르지만 AI 둘이 번갈아 수정할 때 충돌과 회귀가 잦음).

## D-004 delta time 처리

- 상태: 채택
- 날짜: 2026-11-02
- 결정
  - 매 프레임 `time.perf_counter()`로 시각을 재고 `FrameClock`이 dt(초)를 계산합니다.
  - 첫 프레임 dt는 0, 시각이 거꾸로 가면 0, 최대값은 `MAX_DELTA_TIME = 0.1`초로 제한합니다.
  - `open_canvas(sync=True)`로 수직 동기화를 켭니다. 동기화가 안 되는 환경에서도 로직은 dt 기반이라 속도가 같습니다.
- 이유
  - `pico2d.get_time()`은 밀리초 단위(SDL_GetTicks)라 고FPS에서 dt 오차가 크고, SDL에 의존해 테스트가 어렵습니다.
  - 창을 드래그하거나 디버거로 멈춘 뒤 큰 dt가 들어오면 캐릭터가 벽을 통과하는 등 로직이 튈 수 있습니다.
- 대안: 고정 시간 간격(fixed timestep) 갱신. 물리 정확도가 중요해지면 다시 검토합니다.

## D-005 좌표계: 칸 좌표와 픽셀 좌표 분리

- 상태: 채택
- 날짜: 2026-11-02
- 결정
  - 게임 로직은 칸 좌표 `(col, row)`를 씁니다. `(0, 0)`은 맵의 왼쪽 아래 칸입니다.
  - 픽셀 좌표는 렌더링에서만 `Grid`로 변환해 사용합니다. 원점은 화면 왼쪽 아래(pico2d 규칙)입니다.
  - `Grid.tile_to_pixel()`은 실수 칸 좌표를 받아, 칸 사이를 이동하는 모습을 보간해 그릴 수 있습니다.
  - 카메라가 필요해지면 `Grid`의 `origin_x/origin_y`(또는 별도 카메라 오프셋)로 확장합니다.
- 이유: 칸 단위 이동·공격 판정을 단순하게 유지하고, 화면 크기나 카메라가 바뀌어도 로직은 바뀌지 않게 합니다.
  pico2d와 같은 방향(아래→위)으로 row를 정해 변환 실수를 줄입니다.

## D-007 테스트 도구: 표준 unittest

- 상태: 채택
- 날짜: 2026-11-02
- 결정
  - Python 표준 라이브러리 `unittest`를 씁니다. (`python -m unittest`)
  - 스모크 테스트는 SDL 더미 드라이버(`SDL_VIDEODRIVER=dummy`)로 `main.py --frames 30`을 실행합니다.
- 이유: 추가 의존성 없이 어디서나 실행할 수 있습니다. pytest도 unittest 테스트를 그대로 실행할 수 있어 나중에 바꾸기 쉽습니다.
- 참고: 더미 드라이버로는 그려진 화면을 읽을 수 없으므로, 그리기 확인이 필요하면 `xvfb-run` 등 가상 디스플레이를 씁니다.
