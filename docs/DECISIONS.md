## D-003 모듈 구조와 계층 분리

- 상태: 채택
- 날짜: 2026-11-02

- 대안: 파일 하나에 모든 코드 작성 (초기엔 빠르지만 AI 둘이 번갈아 수정할 때 충돌과 회귀가 잦음).

## D-004 delta time 처리

- 상태: 채택
- 날짜: 2026-11-02
- 결정
  - 매 프레임 `time.perf_counter()`로 시각을 재고 `FrameClock`이 dt(초)를 계산합니다.
  - 첫 프레임 dt는 0, 시각이 거꾸로 가면 0, 최대값은 `MAX_DELTA_TIME = 0.1`초로 제한합니다.
  - `open_canvas(sync=True)`로 수직 동기화를 켭니다. 동기화가 안 되는 환경에서도 로직은 dt 기반이라 속도가 같습니다.
- 이유
  - `pico2d.get_time()`은 밀리초 단위(SDL_GetTicks)라 고FPS에서 dt 오차가 크고, SDL에 의존해 테스트가 어렵습니다.
  - 창을 드래그하거나 디버거로 멈춘 뒤 큰 dt가 들어오면 캐릭터가 벽을 통과하는 등 로직이 튈 수 있습니다.
- 대안: 고정 시간 간격(fixed timestep) 갱신. 물리 정확도가 중요해지면 다시 검토합니다.

## D-005 좌표계: 칸 좌표와 픽셀 좌표 분리

- 상태: 채택
- 날짜: 2026-11-02
- 결정
  - 게임 로직은 칸 좌표 `(col, row)`를 씁니다. `(0, 0)`은 맵의 왼쪽 아래 칸입니다.
  - 픽셀 좌표는 렌더링에서만 `Grid`로 변환해 사용합니다. 원점은 화면 왼쪽 아래(pico2d 규칙)입니다.
  - `Grid.tile_to_pixel()`은 실수 칸 좌표를 받아, 칸 사이를 이동하는 모습을 보간해 그릴 수 있습니다.
  - 카메라가 필요해지면 `Grid`의 `origin_x/origin_y`(또는 별도 카메라 오프셋)로 확장합니다.
- 이유: 칸 단위 이동·공격 판정을 단순하게 유지하고, 화면 크기나 카메라가 바뀌어도 로직은 바뀌지 않게 합니다.
  pico2d와 같은 방향(아래→위)으로 row를 정해 변환 실수를 줄입니다.

## D-013 주인공 칸 이동 방식과 이동 관련 임시값

- 상태: 구현 방식 확정 / 수치는 임시
- 날짜: 2026-11-03
- 결정
  - 논리적 위치는 정수 칸 좌표. 한 칸 이동을 **시작하는 순간 논리 위치가 도착 칸**으로 바뀌고, 그림만 출발→도착을 dt로 보간합니다.
    (나중에 충돌·적 판정에서 '이동 중인 칸'을 미리 차지한 것으로 다룰 수 있습니다.)
  - 키를 누르고 있으면 한 칸 도착 시 남은 시간을 다음 칸 이동에 넘겨 끊김 없이 이어갑니다. 큰 dt도 시간 손실 없이 처리합니다.
  - 화면(격자) 밖으로 나가는 축의 이동은 막습니다. 대각선으로 화면 끝에 붙으면 남은 한 축으로 미끄러집니다.
  - 바라보는 방향: 이동 중에는 실제 이동 방향, 멈춰 있으면 누른 방향. 대각선은 현재 방향이 두 성분 중 하나면 유지하고, 아니면 측면(좌/우) 그림을 씁니다.
  - 같은 행동에 키가 둘(W와 ↑ 등)일 때 하나만 떼어도 다른 키가 눌려 있으면 행동을 유지합니다 (`pico2d_input`).
- 임시값 (`game/config.py`): `PLAYER_MOVE_SPEED = 6.0`칸/초(PRE-PRD 2.1 [제안] 후보), `PLAYER_DIAGONAL_TIME_SCALE = 1.0`(PRE-PRD 2.1 [미정], 결정 전까지 직선과 같은 시간),
  `PLAYER_IDLE_FRAME_DURATION = 0.18`초, `PLAYER_WALK_FRAME_DURATION = 0.1`초.
- 이동 중 입력 버퍼(PRE-PRD 2.1 [제안])는 구현하지 않았습니다. 이동 중 짧게 눌렀다 뗀 키는 무시될 수 있습니다.

## D-014 주인공 상태 머신 구성과 스프라이트 형식

- 상태: 확정 (구조) / 임시 (에셋)
- 날짜: 2026-11-03
- 결정
  - `transitions==0.9.3`을 `requirements.txt`에 고정했습니다. (사용자 승인 2026-11-03)
  - `game/player/state_machine.py`의 `STATES`·`TRANSITIONS` 목록으로 상태와 전환 규칙을 관리합니다. 현재는 `idle`, `walk`만 있고,
    나머지 상태는 기능을 개발할 때 목록에 추가합니다. `auto_transitions=False`로 임의 전환(`to_<상태>()`)을 막았습니다.
  - 상태 머신은 상태 전환만 맡고, 이동(`movement.py`)·애니메이션(`animation.py`)·방향(`facing.py`)은 별도 모듈입니다. 상태가 바뀌면 새 상태 애니메이션을 첫 프레임부터 재생합니다.
  - 스프라이트 시트 형식: `assets/images/player/<상태>_<front|back|side>.png`, 프레임 32×48 × 5장 가로 배치. 발끝(그림 아래 가운데)을 칸의 아래 가운데에 맞춰 그립니다.
  - 도트 선명도: 원본 크기 그대로 정수 픽셀 위치에 그리고, SDL 확대 품질 힌트를 nearest(`"0"`)로 둡니다.
  - 이미지를 불러오지 못하면 폰트와 같이 경고만 출력하고 그림을 생략합니다. (SDL 더미 드라이버 스모크 테스트에는 렌더러가 없어 이미지를 불러올 수 없음.) 에셋 규격은 `tests/test_player_assets.py`가 따로 검사합니다.
- 에셋은 참고 시트에서 자동 추출한 임시 에셋입니다. 문제점은 `assets/README.md` 참고.
