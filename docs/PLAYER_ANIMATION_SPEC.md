# 주인공 애니메이션 에셋 제작 명세 v1.0

> 기준: `PRE-PRD.md` 2.6~2.7절, `assets/concepts/player_character_concept_v1.png`.
> **상태 표기:** [확정] 사용자가 선택함, [제안] 제작 추천값, [미정] 아직 결정하지 않음.

## 1. 캐릭터 디자인 [확정]

- 기존 컨셉 시트 중 두 번째 버전(키 유지, 머리 약간 축소, 더 날씬한 체형)을 기준으로 합니다.
- 낡은 갈색 후드, 그림자로 가린 상안면, 보이는 하관, 어깨망토와 장갑, 어두운 모험가 복장.
- 초반 장비는 낡은 검이며, 이후 다른 검을 장착/교체할 수 있어야 합니다.
- Idle에는 망토가 은은하게 흔들리는 느낌을 반영합니다.
- 주인공 원본(제작) 크기는 **32×48px**, 타일은 32×32px입니다. 화면에는 2배(64×96px, 타일 64×64px)로 확대해 그립니다 (2026-11-03, DECISIONS D-017). 그림 크기와 논리 충돌 크기는 별개입니다.

## 2. 방향 수 [확정]

- 원본: `front`(앞), `back`(뒤), `side`(옆) **3방향**.
- 화면 표시는 `front`, `back`, `left`, `right` **4방향**이며 왼쪽/오른쪽은 측면 이미지의 좌우반전으로 표현합니다.
- 실제 이동 방향은 ~~**8방향**입니다. 대각선 이동 시 어느 방향 스프라이트를 재생할지는 구현 시 정합니다.~~
  **상하좌우 4방향**입니다. 대각선 이동은 없습니다. (2026-11-03 변경)
- **주의:** 좌우 반전만 하면 장갑·망토·무기 손잡이의 좌우 배치도 반전됩니다. 비대칭 장식 또는 무기 장착 위치가 어색하지 않은지 확인합니다.

## 3. 애니메이션 상태

| 상태 | 의미 | 초기 프레임 제안 | 비고 |
|---|---|---|---|
| `idle` | 정지, 망토 흔들림 | 4~5 | 반복 재생 |
| `walk` | 칸 이동 | 4~5 | 반복 재생, 4방향 이동 (2026-11-03 변경). [제안] 32×48 크기에서도 다리 교차가 보이도록 프레임 간 자세 차이를 크게 |
| `jump` | 적의 하단 공격에 대응 | 4~5 | 점프 높이/무적 여부 미정 |
| `dodge` | 빠른 회피 이동 | 4~5 | 점프와 별개 |
| `sword_attack` | 검 공격 | 4~5 | 공격 판정 및 타수 미정 |
| `parry` | 타이밍 기반 패링 | 4~5 | 패링 판정 시간은 프레임 수와 분리 |
| `hurt` | 일반 피격 순간의 자세 | 4~5 | 짧은 피격 모션 |
| `stun` | 강한 공격 후 기절 | 4~5 | **약 2~3초 기절**, 프레임 종료와 별개 |

- 사용자 요청은 **각 상태·원본 방향별 4~5프레임 정도**로 시작하는 것입니다. 최종 장수는 실제 화면에서 조정합니다.
- 수량 추산: **8상태 × 3원본 방향 × 4~5프레임 = 96~120장** (좌우 반전은 별도 파일 수에 포함하지 않음).
- `stun`에서 2~3초 동안 4~5프레임을 느리게 재생할 필요는 없습니다. 진입 모션 재생 후 마지막 프레임 유지 또는 미세한 흔들림 반복을 추천합니다.
- `dead`, `cast` 및 공격 콤보별 추가 애니메이션은 **아직 미확정**입니다.

## 4. 구현 지침

- **[확정]** Python `transitions`로 주인공 상태 전환 관리. 패키지의 설치 및 버전 고정은 실제 FSM 기능 구현 시 처리합니다.
- **[제안]** 상태 전환 조건(예: jump 중 피격, parry 성공 시 행동 전환), 동작 중 입력 허용 여부는 구현 전 검토합니다.
- **[제안]** 점프는 논리적 격자 위치와 별도로 '공중' 여부 또는 높이를 관리하고, 하단 공격 판정과 연동합니다. 시각적 높이 이동을 충돌 판정의 픽셀 좌표로 대신하지 않습니다.
- **[제안]** 무기는 캐릭터 본체 이미지와 별도 레이어로 제작하는 것이 장비 교체에 유리합니다. 필요시 각 프레임에 무기 장착 기준점 정보를 둡니다.
- **[제안]** 별도 에셋 제작 시 각 프레임의 발 위치(앵커)를 정렬하고 투명 배경 PNG를 사용합니다.

## 5. 제작 파일 구조 예시 [제안]

```text
assets/images/player/
  idle/front.png   (2026-11-03 구현: <상태>/<방향>.png 폴더 구조)
  idle/back.png
  idle/side.png
  walk/front.png
  walk/back.png
  walk/side.png
  jump/front.png
  ...
  dodge_*.png
  sword_attack_*.png
  parry_*.png
  hurt_*.png
  stun_*.png
```

> 파일마다 한 방향의 여러 프레임을 묶은 스프라이트 시트를 사용하거나, 프레임별 PNG 파일을 사용할 수 있습니다. 최종 규격은 구현 직전 결정합니다.
